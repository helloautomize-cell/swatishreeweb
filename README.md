# EVE Women and Fertility Clinic website

Marketing website for EVE Women and Fertility Clinic, Gunjur, Bangalore. Built with Next.js (App Router), TypeScript and Tailwind CSS.

## Layout

- `src/` application code
- `resources/` source-of-truth material (read-only; copy from it, never edit)
  - `docs/` master prompt, site plan, content file, client data, credentials facts, image map
  - `reference/` approved visual reference
  - `images/` delivered photography and logo masters with `image-manifest.json`
  - `assets/` generated badges, spot icons and scenes
  - `content/` parsed per-page content (pipeline output)
- `scripts/` build and audit scripts
- `public/` static output, including processed images

## Commands

```bash
npm run dev                    # development server
npm run build                  # production build (runs build-check first)
npm run lint                   # ESLint
npm run typecheck              # tsc --noEmit
npm run test:e2e               # Playwright (needs a running dev server)
npm run audit                  # read-only content and resource audit
npm run launch-check           # fails while any [CONFIRM] item is open; writes client-inputs-needed.md
node scripts/split-content.mjs # regenerate resources/content/ from the source content file
node scripts/audit-content.mjs --prepare-resources # verify and copy the supplied v2 resources
```

## Source files

The current build brief is `resources/docs/WINDSURF-MASTER-PROMPT-EVE.md`. Page copy comes from `resources/docs/new-website-content.md`, copied unchanged from `new-website-content_swati.md`. URLs, navigation, schema and global copy blocks come from `resources/docs/site-plan.md`. Visual layouts come from `resources/reference/eve-styleguide-final.html`. Client facts come from `resources/docs/eve-client-data.md`. Image slots come from `resources/images/image-manifest.json`.

The final reference uses a left-side cut-out hero, concern rows, a Why EVE bento layout, an editorial doctor section, a right-side first-visit guide and plain white service cards. Older references are historical, not the current visual contract. Page wording is preserved except for the approved removal of named hospitals from Home; hospital names belong on About and the doctor profile only.

## Resource status

The v2 source set is installed. Phase 1 rebuilt `/styleguide/` to the final reference; Phase 2 added the full site shell (utility bar, sticky header with three accessible mega menus, mobile drawer + action bar, floating WhatsApp, deep-moss footer, cookie banner, breadcrumbs, custom 404, noindex `/thank-you/`). Phase 3 built the content pipeline: `scripts/split-content.mjs` splits the source file into `resources/content/*.md` (46 pages + 3 posts + 404), Zod validates the YAML frontmatter, and `src/app/[[...slug]]/page.tsx` renders all 49 routes through shared templates (detail, hub, standard, post) with one JSON-LD graph per page. Phase 5 added the blog index with category filters, per-page OG cards generated by scripts/og-images.mjs (public/og/), sitemap.xml, SITE_INDEXABLE-aware robots.txt, llms.txt/llms-full.txt generated by scripts/gen-llms.mjs (both wired into prebuild), and site-wide link/image QA in the content spec. Lighthouse on the local production build reports mobile medians of 91-95 performance, 100 accessibility, 0 CLS across home, IVF, PCOS and one post. The image pipeline now converts all 38 manifest photos with normal Sharp processing (C2PA preservation waived by the user); D1/D2 stay withheld pending background removal. Phase 4 built the production Home page (15 Part-7.1 sections parsed from `resources/content/index.md` via `src/lib/home.ts`), the polished detail template (split hero with lead image or badge panel, At-a-glance card, sticky TOC with Book card, native step-icon process lists, stacked mobile tables), hub groups with how-to-choose and ART panels, the doctor profile (facts card, quote cards, timelines, mobile "Show all" chip groups), the journey rail (4 stages with stage icons, ART panel), and legal pages with a left TOC and print styles. `[CONFIRM]` and `[date]` tokens both render as dev-only chips and are hidden from production output and JSON-LD. 

The Why EVE icon tiles and first-visit illustrations use the final reference's inline SVG artwork and finite micro-animations, with reduced-motion fallbacks. The resource manifest and approved source documents are unchanged.

The original documents, legacy photography, brand logos and badge assets are retained. `eve-legacy-phase0-20261006.tar` is a local, Git-ignored snapshot of the previous application and resources. It is not public site content. The resource-preparation command requires that snapshot and refuses to overwrite different canonical document copies or existing image files. It only replaces the archived legacy manifest with the ZIP manifest.

Values not yet confirmed by the client remain `[CONFIRM]` items and must not appear in production output. No phase is complete until its checks have been verified and reported. Work stops at each approval gate. Do not create branches, commit, push, deploy or enable indexing without the user's specific instruction.
